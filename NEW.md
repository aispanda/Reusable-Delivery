# Create new work

If you arrived here directly, read [DELIVERY.md](DELIVERY.md) first and resolve the guide SHA before continuing.

Required reading: [CORE.md](CORE.md), completely, at the same guide commit as [DELIVERY.md](DELIVERY.md) and this route. Do not execute from this route alone. Missing required content blocks dependent work as described in the entry.

1. Establish the beneficiary, outcome, scope, exclusions, known facts and open decisions from the request and relevant sources. Check for existing related work before creating a duplicate. Use MIGRATE if this is actually an existing story.
2. Confirm the intended repository, folder, current branch, existing changes and authorization. Reuse an appropriate repository/folder; create a new repository only when authorized. Ask for a genuinely missing destination or decision rather than inventing one. No fixed artifact count is required.
3. Create `story.md` using CORE’s copyable template. Define observable criteria with stable IDs. Preserve requirements already agreed in the brief; label new interpretations as proposals. Apply CORE’s sanitization mapping and source/published criterion comparison. Keep unknown owners, models, inputs and results explicit. State the concise solution and link necessary design/research detail.
4. Outline bounded steps with one executor each; expand the immediate eligible step with inputs, output, checks, authority and stop/recovery conditions. Apply CORE’s execution and review rules.
5. Apply CORE’s publication checks. After GitHub readback, create/update the authorized ClickUp item with title, optional story sentence, folder link and story link; use its owner/date/status fields. Apply CORE’s preservation and concurrency checks before replacing any existing ClickUp description. Verify the saved pointer and fields.
6. Continue eligible work already authorized, recording results using CORE. Story creation alone is not permission to build or deploy. Report verified results, remaining decisions and the next action.

Optional: [worked example](EXAMPLE.md) if the format needs illustration; [validation history](VALIDATION.md) for an audit. Neither is required for routine creation.
