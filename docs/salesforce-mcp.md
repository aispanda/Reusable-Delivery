# Salesforce MCP setup and recovery

Use this runbook when MCP setup, recovery, or server selection is needed. An agent IDE must support the Salesforce authentication flow for the chosen server. Substitute placeholders locally; never put an org's URLs, identities, client IDs, tokens, secrets, or record data in public documentation. Access depends on the org edition, API/MCP eligibility, enabled features, licensing, and the user's permissions. Check the relevant server and entitlement in Setup. Salesforce [may bill hosted MCP usage](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/hosted-mcp-servers-overview.html). Use the least access needed; normal Salesforce sharing, object, and field permissions still apply.

## 1. Reconnect an existing server

If the server is already registered in this agent environment, use its existing approved configuration. For Codex, identify the local server name with `codex mcp list`, then run `codex mcp login <SERVER_NAME>`. Complete sign-in and consent in the browser, wait for the client to confirm authorization, and reconnect or reopen the agent session if it still shows a stale tool list. Then run the read probe below. If registration is missing, start with Setup.

## 2. Inspect the org and prepare the client

1. In Salesforce **Setup**, search **MCP Servers**, select it under API Catalog, then open **Salesforce Servers**. Read each needed server's activation status; open **Details**, copy its **Server URL**, and inspect the **Tools** tab. An active server is not proof that the client is authorized or that a tool can be called. An administrator activates only approved servers; activation can take up to two minutes. See [Activate MCP Servers](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/activate-mcp-servers.html) and the [standard server catalog](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/servers-reference.html).
2. Use the copied URL. If constructing it is necessary, follow [Find Your Server URL](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/server-urls.html): production standard format is `https://api.salesforce.com/platform/mcp/v1/platform/<SERVER>`; sandbox standard format inserts `/sandbox` before `/platform`. My Domain, Developer Edition, scratch, and custom server formats differ. Preserve the `platform/` or `custom/` prefix and the correct login authority.
3. In **Setup → External Client App Manager**, first inspect an existing approved External Client App (ECA) for this client, exact redirect, appropriate user access, and scopes. For a new app or policy change, an authorized admin follows [Create an External Client App](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/create-external-client-app.html): enable OAuth, register the client's exact callback, select `mcp_api` and `refresh_token`, issue JWT-based access tokens for named users, and configure security and user preauthorization as appropriate. Use an authorization-code client with PKCE, and verify its callback and client-registration support against its vendor instructions. Salesforce says Connected Apps are not supported for hosted MCP authentication; scratch-org ECA provisioning has a separate packaging process. A new ECA can take up to 30 minutes to become available. Never embed a secret in a desktop client or public file.
4. In the agent IDE, configure a **remote streamable HTTP** server with the copied URL and the approved ECA's consumer key as client ID. Follow the client's OAuth login and consent flow. Salesforce documents [client connection requirements and tested clients](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/client-connection-overview.html) and [Cursor configuration](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/cursor.html); another compatible client can work if it supports OAuth authorization code with PKCE and the required callback and registration. Agentforce Vibes has its own auto-enabled connection path; follow its documentation.

For **Codex CLI or IDE**, which share MCP configuration, the [official Codex MCP instructions](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) support a pre-registered client:

```sh
codex mcp add salesforce-headless --url '<SERVER_URL>' --oauth-client-id '<ECA_CONSUMER_KEY>'
codex mcp list
codex mcp login salesforce-headless
```

Register the **exact callback printed by `codex mcp add`** with the ECA before login; issuer support and the server URL affect the callback. Coordinate the registration with the admin. This example uses a public client and no secret. If the client/provider cannot meet the callback or OAuth requirements, stop and resolve compatibility with the admin; don't guess or bypass the controls. Do not paste authorization URLs, tokens, or credentials into logs or tickets.

## 3. Verify the MCP connection

1. Confirm the selected server and tool list in the IDE. For [Headless 360](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/headless-360-mcp.html), run **`discover` → `describe` → `dispatch_readonly`** for a small, authorized read. Inspect the described operation and parameters before dispatch. A successful server list is not a successful read. Use other servers' listed read tools where relevant.
2. Confirm the authenticated org and identity privately. If the CLI also needs setup or repair, use the independent [CLI recovery guide](salesforce-cli.md). A successful MCP read does not establish CLI access.
3. Record sanitized evidence privately: server name, active/connected status, tool and read-probe outcome, intended environment and identity match, time, and any redacted error. Avoid raw JSON or sensitive identifiers. If eligibility, authorization, identity, or a required read fails, mark that dependency blocked and do not proceed with dependent changes. Use the browser for Setup, admin configuration, login, or necessary UI acceptance; use supported MCP/CLI tools for routine org work.

## 4. Choose the smallest suitable server

| Task | Official server or tool | Use and boundary |
| --- | --- | --- |
| Discover org operations and read configuration | [Headless 360](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/headless-360-mcp.html) | Discover, describe, then read-only dispatch; writes require an authorized operation. |
| Understand schema and metadata types | [Salesforce API Context](https://developer.salesforce.com/docs/platform/api-metadata/guide/meta-salesforce-api-mcp-intro.html) | Inspect supported API/schema definitions and type constraints before generating or querying. Check available tools and edition. |
| Generate supported metadata | [Metadata Experts](https://developer.salesforce.com/docs/platform/agentforcevibes/guide/afv-mdexperts.html) | `execute_metadata_action` supports registered metadata types; it is not a general org export. |
| Local development and metadata lifecycle | [Salesforce DX MCP](https://developer.salesforce.com/docs/platform/sfdx-dev/guide/sfdx-dev-mcp-server.html) and [CLI](https://developer.salesforce.com/docs/platform/salesforce-cli-reference/guide/cli_reference.html) | DX MCP is a separate local server, uses locally authorized orgs, and supports scoped toolsets. Use DX tools or CLI for retrieve, validate and deploy as supported; allowlist the intended org and needed toolsets. |
| CRM records | [SObject Reads](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/sobject-reads.html), [Mutations](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/sobject-mutations.html), [Deletes](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/sobject-deletes.html), [All](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/sobject-all.html) | Prefer Reads for reads and Mutations for create/update; Deletes or All expose deletion and require specific delete authorization. For approved bulk CSV operations use the separate [CLI data commands](https://developer.salesforce.com/docs/platform/salesforce-cli-reference/guide/cli_reference_data.html). |
| CMS content | [Content Read-Only](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/content-readonly.html), [Content Write](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/content-write.html) | Inspect the actual Tools tab and reference for each operation. Publish or upload only if supported and authorized; do not assume binary upload exists. Use the applicable [CMS Connect REST API](https://developer.salesforce.com/docs/platform/connect-rest-api/guide/intro_input.html) if needed. |
| Unified customer data, if applicable | [Data 360](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/data360-mcp.html) | Separate product and entitlement from Headless 360; use for supported Data 360 queries. |

Consult the live [standard server catalog](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/servers-reference.html) and the org's Tools tab for other product-specific servers and current availability.

## 5. Custom Salesforce-hosted server, only if needed

Standard servers have fixed tool sets. If they do not cover a persona's approved workflow, an administrator can follow [Custom MCP Servers](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/custom-servers.html) to create a focused custom server in Setup, curate standard tools, and add eligible [API Catalog endpoints](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/api-catalog.html), [autolaunched Flows](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/flows.html), or [Apex invocable actions](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/invocable-actions.html) and other documented Apex options. Review input/output contracts, authenticated-user permissions, side effects, and permission boundaries; expose only required operations. Verify in a sandbox with the intended user and read/write controls, then follow the organization's approval and deployment process before activation elsewhere. API Catalog includes only registered endpoints; verify availability. The [API example](https://developer.salesforce.com/docs/platform/api-catalog-connectapi/guide/create-custom-salesforce-mcp-servers.html) describes activation and asset changes.

## 6. Troubleshooting

| Symptom | Check |
| --- | --- |
| Server missing or inactive | Check edition, feature/permission eligibility, Setup catalog, activation, and propagation; ask the admin to approve changes. |
| Active but connection or tools fail | Separate activation from client OAuth and user permissions; check copied URL, org type, prefix, identity, tools, and object/field/sharing access. |
| OAuth error, including `scope parameter not supported` | Treat this as an OAuth/client or authority diagnostic, not evidence that the server is inactive. Check exact callback, client ID, requested scopes, PKCE/JWT requirements and ECA policy; try a fresh login through the same intended authority. Do not alter scopes, policies, or activation without approval. See [authentication troubleshooting](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/authentication-issues.html). |
| Tool unavailable or rejected | Recheck current tool reference, entitlement and permissions; use a supported alternative only within the authorized scope. Capture a sanitized error and block dependent work. |
