# Reuse an existing design system

Start with a working It’s a Plan pattern. Keep the host site’s workflow and data. Fill component gaps from the original libraries It’s a Plan uses, using one preset and one token source.

This guide is a worked handoff for the AI Spanda Content Studio. Its install steps and acceptance checks are for an isolated implementation pilot. The guide records source selection and wiring. Studio integration and accessibility evidence are still pending.

Give builders and AI the [short pattern picker](choose-a-ui-pattern.md) first. Use this guide for exact source lookups, [library choices](#library-choices-for-a-consistent-studio) and implementation.

## Studio starting point and foundations

- Use the existing Astro [Studio route](https://github.com/aispanda/aispanda-web/blob/078a7b07bdd7b8cfc7ac7f6f519dee85263b11fd/src/pages/studio/index.astro) and [Tiptap schema](https://github.com/aispanda/aispanda-web/blob/078a7b07bdd7b8cfc7ac7f6f519dee85263b11fd/src/scripts/studio-tiptap-schema.mjs). The [AI-91 authoring requirements](https://github.com/aispanda/aispanda-web/blob/078a7b07bdd7b8cfc7ac7f6f519dee85263b11fd/docs/CONTENT_AUTHORING_REQUIREMENTS.md#professional-structured-editor--ai-91) govern the supported blocks. The recorded site baseline is `078a7b0`. Confirm the base before starting a pilot.
- The [Astro component review at `36504ae`](https://github.com/aispanda/aispanda-web/commit/36504ae192f0303fa1daf776b4c33eee8d1da20b) adds public components such as StatusBadge and SectionHeading and touches shared CSS. Inspect it for overlapping patterns before adding equivalents. The commit has no Studio route changes. Pilot from a clean isolated checkout.
- Use the official shadcn **Radix + Neutral + Lucide** preset with Inter for the Studio pilot. Record the selected preset code. This is a stock starting point informed by the reference app's [New York, Neutral and Lucide configuration](https://github.com/croffasia/itsaplan/blob/135bc5f52bff00567e999fe25420199f136fc4e4/apps/web/components.json), whose local wrappers use both Radix and Base UI. The pilot uses one primitive library by default.
- Use the preset's semantic variables for background, text, muted content, borders, focus and destructive states. Keep them in one Studio stylesheet. Mount overlay portals within the Studio token scope or scope the tokens to the Studio page root. Keep Tailwind's global reset out of the shared site stylesheet and check for conflicts with existing Studio styles. Use the existing Astro site styles for the public pages and public article preview. Use the site's current appearance behavior in the pilot and check each supported mode. The reference for quiet chrome and readable type is [It’s a Plan’s design system](https://github.com/croffasia/itsaplan/blob/135bc5f52bff00567e999fe25420199f136fc4e4/DESIGN.md), with [live token definitions](https://github.com/croffasia/itsaplan/blob/135bc5f52bff00567e999fe25420199f136fc4e4/apps/web/src/app/globals.css). [Inter](https://github.com/rsms/inter) is the typography source for Studio interface text.
- Use the [It’s a Plan repository](https://github.com/croffasia/itsaplan) for pattern reference. Any reuse of its app source or styles needs a separate license review. The reference app's terms are in its [AGPL-3.0 license](https://github.com/croffasia/itsaplan/blob/135bc5f52bff00567e999fe25420199f136fc4e4/LICENSE). Install original shadcn components from the official registry and record the version, source and dependency notices for the files the CLI adds. [shadcn/ui license](https://github.com/shadcn-ui/ui/blob/main/LICENSE.md).

## Install and compose

1. In the isolated **site** checkout, use its lockfile and package manager. Check the existing `@/` alias, then follow the [shadcn Astro existing-project setup](https://ui.shadcn.com/docs/installation/astro#existing-project). Add the Astro React integration and Tailwind v4 Vite integration if missing. Use [shadcn/create](https://ui.shadcn.com/create) for stock preset settings. Use the existing-project initialization path, and review the generated stylesheet change before connecting it to Studio. Record the CLI version, preset code and installed paths in the pilot handoff.
2. Preview the CLI changes, then install the small starter set as the controls are wired. The example uses the official CLI entry point. Substitute the version recorded in the pilot for `latest` when repeating the install. Review the listed dependencies and generated files, including any preset CSS. [CLI options](https://ui.shadcn.com/docs/cli#add).

   ```sh
   pnpm dlx shadcn@latest add --dry-run button dialog dropdown-menu popover tooltip
   pnpm dlx shadcn@latest add button dialog dropdown-menu popover tooltip
   ```
3. Keep the Studio shell, static labels, article preview and editor document in their existing Astro and Tiptap layers. Mount a React island for controls that share interactive state. Wire its callbacks to the current editor and Studio operations. Keep native controls and existing working interactions where they already meet the need. Keep public pages clear of the new CSS or client bundle.
4. Start with a formatting button and toolbar tooltip, the Insert menu and one existing dialog flow. Keep the existing command mapping, editor selection, keyboard navigation, focus restoration and dialog behavior across those changes. Use the [pattern picker](choose-a-ui-pattern.md) to pick the controls. Keep the existing live announcements for save status.
5. Preserve the current server authorization and sanitization, revision and autosave semantics, preview renderer and explicit publishing confirmation. New users are Commenters, Authors work on drafts, and Publishers or Administrators can publish. The UI invokes the existing guarded flows. Use fixture or emulator identities and sample articles for every role, including any publish and failure checks.

Record the task, chosen component ID or host path, why it fits and which states to verify in the [component spec](templates/03-component-spec.md).

Common decisions: use a dropdown menu to **run** one of a few actions, a select to **store** one of a few values, and a command menu to **search for an action**. Use a popover for brief work at the trigger, a dialog for a focused task, and a sheet for secondary settings at the screen edge. Keep draft save status inline, conflict and failure messages visible, and toasts for brief confirmations.

### Library choices for a consistent Studio

Use **shadcn/ui with Radix, Neutral, Lucide and Inter** as the Studio starting point. The main cues from It’s a Plan are quiet neutral surfaces, separation through spacing and background, clear type hierarchy and one primary action in each view. Use stock variants and a shared set of tokens across the toolbar, menus, panels and dialogs. The original app uses both Radix and Base UI. The Studio defaults below use Radix for its shadcn controls.

| Use for | Studio default or condition | Original source |
| --- | --- | --- |
| Page shell and simple controls | Keep existing Astro markup and native controls. | [Astro](https://github.com/withastro/astro) |
| Interactive controls | Use official shadcn/ui components with the same Radix preset. Use React for the interactive Studio island. | [shadcn/ui](https://github.com/shadcn-ui/ui), [Radix UI](https://github.com/radix-ui/primitives), [React](https://github.com/facebook/react) |
| Color, spacing and motion | Use one Neutral preset and Tailwind CSS in Studio. Keep the preset animation dependency if the chosen components require it. | [Tailwind CSS](https://github.com/tailwindlabs/tailwindcss), [tw-animate-css](https://github.com/Wombosvideo/tw-animate-css) |
| Icons and interface type | Use Lucide throughout the Studio controls and Inter for Studio interface text. | [Lucide](https://github.com/lucide-icons/lucide), [Inter](https://github.com/rsms/inter) |
| Theme switching | Use the host site's appearance behavior. It’s a Plan’s `next-themes` setup is a reference for its Next.js app. | [next-themes](https://github.com/pacocoursey/next-themes) |
| Structured writing | Keep Studio’s existing Tiptap editor, schema and command mappings. | [Tiptap](https://github.com/ueberdosis/tiptap) |
| Searchable actions and toasts | Use the shadcn Command wrapper when a searchable action list is needed. Use the shadcn Sonner wrapper for transient confirmations when needed. | [cmdk](https://github.com/pacocoursey/cmdk), [Sonner](https://github.com/emilkowalski/sonner) |
| Searchable form value | Start with the existing value picker or Select. Consider the linked Base UI Combobox only when inline search is essential and the existing picker cannot support it. | [Base UI](https://github.com/mui/base-ui) |
