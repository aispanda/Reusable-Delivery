# Human review checklist (draft)

Use before handoff for the primary flow and any component with new interaction. Record who, when, device, browser, assistive technology and result. An agent's screenshot inspection does not complete any line.

Required minimum
- Keyboard only: complete the primary flow without a mouse. Focus is always visible and never hidden behind fixed content, order follows reading order, and nothing traps focus except an open dialog, which returns focus when closed.
- Screen reader: complete the primary flow with the pair named in the brief (for example VoiceOver with Safari on macOS, or NVDA with Firefox or Chrome on Windows). Names, roles, states and status messages are announced and make sense.
- Visual review: layout, hierarchy and brand fit at the narrowest and widest supported widths, judged by the person who approves design.

Add when the brief or risk calls for it
- Zoom: 200 percent text, and a 320 pixel wide view with no lost content and no sideways scrolling for text.
- Forced colors: controls, focus and states remain visible in Windows contrast themes; browser emulation is only a first look.
- Touch on a real phone: targets easy to hit, no content reachable only by hover.
- Reduced motion: motion stops or reduces when the system setting is on.
- Native controls on each supported operating system: select, date and file inputs operated by keyboard.

Result per line: pass, fail with note, or not done with reason.
