# Migrate existing work

If you arrived here directly, read [DELIVERY.md](DELIVERY.md) first and resolve the guide SHA before continuing.

Required reading: [CORE.md](CORE.md), completely, at the same guide commit as [DELIVERY.md](DELIVERY.md) and this route. Do not execute from this route alone. Missing required content blocks dependent work as described in the entry.

1. Inventory the latest story, comments, criteria, decisions, design, research, code and evidence. Confirm source revisions, destination repository/folder, branch, concurrent work and existing authorization. Read relevant prior chats only where they resolve gaps. Distinguish observed results, historical reports, proposals and model opinions; another project’s state is not this project’s evidence.
2. Capture the current ClickUp description verbatim as historical evidence before replacing it. Keep client-identifying originals in approved restricted storage, with an access-controlled mapping to sanitized parameters. Preserve existing attachments and material history. Do not move private content into public Git history.
3. Populate CORE’s story template from the inventory. Preserve agreed criterion IDs and wording, decisions and useful artifact links. Compare source and destination criteria and classify every difference, including sanitization. A missing, inaccessible or unauthorized alteration to a required criterion blocks migration completion. Do not invent evidence, approvals, names, URLs or model identities. Reconcile conflicting facts rather than overwrite them.
4. Reconcile each step against evidence. Keep valid completed work complete; do not restart it merely because the format changed. Reopen checks affected by changed inputs or criteria and leave unverified results NOT RUN. Retain previous execution records, blockers, fixes and review dispositions. Select the next eligible step using CORE.
5. Apply CORE’s publication checks. Read back the published revision and verify access to the folder, story and required evidence. Confirm authority to edit the ClickUp item; refresh its text/comments immediately before writeback and reconcile intervening changes. Replace the current description with title/optional story sentence and the two GitHub links; synchronize owner/date/status fields from their authoritative sources. Read back the result. Preserve the historical snapshot without maintaining two competing current stories.
6. Record the migration revision, source references, differences, preservation checks, unresolved gaps and next action in story history. Execute only remaining work already authorized. A migration does not transfer prior client permissions, fixture reservations or acceptance to a new environment. Failed synchronization remains an explicit blocker, not a claimed success.

Optional: [worked example](EXAMPLE.md) for formatting; [validation history](VALIDATION.md) for an audit. Neither is required for routine migration.
